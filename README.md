# Битва за Респект — фронт

Сайт турниров по Arc Raiders (стример Денис Блим): главная с текущим матчем, рейтинг, профили
игроков, кабинет организатора и оверлей для OBS. Next.js 16 (App Router, TypeScript, Turbopack)
+ React 19 + Tailwind v4.

> **Сайт состоит из двух проектов в разных репозиториях:**
> - **frontend** — этот репозиторий: страницы сайта;
> - **backend** — [arc-battles-back](https://github.com/anbolax1/arc-battles-back): сервер на Go
>   и база данных, откуда сайт берёт все данные.
>
> Сначала запустите бэкенд по инструкции из его README — там же установка программ, база данных
> и загрузка данных с настоящего сайта. Потом — этот фронтенд по шагам ниже. Без бэкенда страницы
> откроются пустыми.

## Как запустить у себя (пошагово)

Команды вводятся в терминале. На Windows используйте **Git Bash** — он ставится вместе с Git:
правый клик по папке → «Open Git Bash here».

### 1. Запустите бэкенд

Пройдите шаги 1–6 из README бэкенда:
[arc-battles-back](https://github.com/anbolax1/arc-battles-back#как-запустить-у-себя-пошагово).
Там установка программ (включая Node.js), скачивание обоих проектов в одну папку, база данных,
сервер и данные с сайта.

Проверка, что бэкенд работает: http://localhost:8080/api/health показывает `{"ok":true,...}`.

### 2. Установите зависимости

```bash
cd frontend
npm ci
```

Займёт пару минут: npm скачает библиотеки в папку `node_modules`. Повторять нужно только когда
в проекте поменялся `package.json`.

### 3. Укажите, где работает бэкенд

Создайте в папке `frontend` файл `.env.local` с двумя строками:

```ini
BACKEND_ORIGIN=http://127.0.0.1:8080
INTERNAL_API_URL=http://127.0.0.1:8080
```

То же самое одной командой:

```bash
printf 'BACKEND_ORIGIN=http://127.0.0.1:8080\nINTERNAL_API_URL=http://127.0.0.1:8080\n' > .env.local
```

- `BACKEND_ORIGIN` — куда сайт пересылает запросы браузера к `/api`.
- `INTERNAL_API_URL` — куда страницы обращаются за данными при отрисовке на сервере.

Если бэкенд запущен на другом порту (например, вы указали в его `.env` строку `PORT=8081`), впишите
здесь этот порт в обе строки. Файл `.env.local` в git не попадает.

### 4. Запустите сайт

```bash
npm run dev
```

Когда в терминале появится `Ready`, откройте:

- http://localhost:3100 — сайт;
- http://localhost:3100/admin — кабинет организатора: войдите под логином `Istwood` с паролем
  из строки `SUPERADMIN_PASSWORD` в `.env` бэкенда;
- http://localhost:3100/overlay — оверлей для OBS.

Терминал не закрывайте: пока он открыт, сайт работает. Остановить — `Ctrl+C`. Правки в коде
появляются в браузере сразу, перезапускать не нужно.

### Если что-то не работает

- **Страницы пустые или пишут «Что-то пошло не так»** — не запущен бэкенд или в `.env.local`
  неверный порт. Проверьте http://localhost:8080/api/health (или ваш порт) и перезапустите
  `npm run dev` после правки `.env.local`.
- **`npm ci` ругается на версию** — нужна Node.js 20 или новее: `node -v`.
- **Не применяются правки стилей в `globals.css`** — остановите сайт, удалите папку `.next/dev`
  и снова запустите `npm run dev`.
- **Порт 3100 занят** — запустите на другом: `npx next dev -p 3200`, и в `.env` бэкенда поменяйте
  `FRONTEND_URL` на `http://localhost:3200`.
- **Не получается войти в кабинет** — пароль организатора задаётся в `.env` бэкенда и применяется
  при его запуске: поправьте `SUPERADMIN_PASSWORD` и перезапустите бэкенд.

### Для разработчика

Перед коммитом — те же проверки, что делает CI перед выкладкой:

```bash
npm run lint
npx tsc --noEmit
npm run build
```

## Возможности

**Сайт:**
- Главная: идущий матч со счётом и картами раундов, анонс запланированного шоу-матча, топ сезона.
- Рейтинг по сезонам (1×1 и команды 2×2), архив сыгранных матчей, расписание шоу-матчей.
- Страница матча: раунды с картами и заданиями сторон, пики-баны, изменение MMR.
- Профиль игрока: теги, график и сводка MMR по сезонам, история матчей, аналитика.
- Правила 3 сезона, хайлайты, заявка на участие.

**Кабинет организатора (`/admin`):**
- Матчи: новый матч одной формой (игроки, тип, ×2) или шоу-матч на дату; пульт матча —
  пики-баны, раунды, зачёт заданий обеих сторон, ручные очки, легендарки, журнал с отменой.
- Оверлей: раскладка виджетов и пресеты для сцен OBS.
- Задания и протоколы, легендарки, сезоны (K и стартовый MMR), игроки, теги, заявки, хайлайты.
- Дизайн сайта: прежний или новый в стиле ARC Raiders — для всех посетителей одним нажатием
  или предпросмотр только в своём браузере.

**OBS-оверлей (`/overlay`):** табло, задания, протоколы, пики-баны и другие виджеты; обновляется
сам по WebSocket.

## Структура

- `src/app/(site)` — публичные страницы; `src/app/admin` — кабинет; `src/app/overlay` — оверлей.
- `src/components/` — `ui/` (база: Button/Pill/Panel…), `domain/`, `admin/`, `overlay/`;
  `surface/` — новый дизайн (стили в `src/app/surface.css`, классы с префиксом `sf-`).
  Страница выбирает вариант через `getDesign()` из `src/lib/design.ts`: общий выбор лежит на
  бэкенде, личный предпросмотр — в cookie `rsp_design`.
- `src/lib/` — `api.ts`/`server-api.ts` (клиент к `/api`), `queries.ts`, `types.ts`
  (зеркало Go-моделей), `ws.ts`, `format.ts`, `display.ts`, `auth.tsx`.

## Выкладка на прод

Split-топология: `brouhub.ru` (этот фронт, :3000) + `api.brouhub.ru` (Go API, :8080) за nginx
+ Let's Encrypt. Выкладка автоматическая: push в `main` — GitHub Actions проверяет код, собирает
сайт и выкладывает его на сервер (`.github/workflows/deploy.yml`). `NEXT_PUBLIC_API_BASE`
вшивается при сборке из `.env.production`.
